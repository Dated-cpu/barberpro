# Улучшение навигации для авторизованного клиента

## Задача
Унифицировать UX: авторизованный клиент остаётся на публичных страницах после входа, а в шапке вместо «Вход / Профиль» видит своё имя и дропдаун с быстрым доступом. Без изменения архитектуры и безопасности.

## Изменённые файлы

| Файл | Изменение |
|------|-----------|
| `src/components/shared/user-menu.tsx` | **Новый** компонент меню пользователя: дропдаун (desktop) и inline-пункты (mobile) |
| `src/components/shared/header.tsx` | Вместо хардкод-ссылок «Профиль / Войти» использует `<UserMenu />` в desktop-блоке и `<UserMenu mobile />` в мобильном меню |
| `src/app/auth/login/page.tsx` | CLIENT после входа остаётся на главной (`/`) вместо редиректа в `/profile` |
| `src/app/(auth)/login/page.tsx` | То же для дублирующего логин-роута (`/login`) |

## Что изменилось

### 1. Unified UX после логина
- Роль `CLIENT` больше не перебрасывается в «личный раздел» — после входа клиент остаётся на публичной странице, где шапка и навигация доступны как раньше.
- ADMIN / BARBER редиректят в свои кабинеты как раньше (поведение не тронуто).

### 2. Шапка (desktop)
- Гость: «Профиль» + «Войти» + «Записаться» — как было.
- Авторизованный клиент: кнопка «👤 Имя» (SVG-иконка человека + имя) с дропдауном:
  - **Личный кабинет** → `/profile`
  - **Мои записи** → `/profile` (раздел истории записей)
  - **Новая запись** → `/booking`
  - **Настройки профиля** → `/profile`
  - **Выйти** → `auth.logout` (CSRF-защищённая мутация), инвалидация кэша, редирект на `/`
- Для BARBER/ADMIN/SUPER_ADMIN дропдаун показывает ссылки на их кабинеты (`/barber`, `/admin`) — публичную шапку могут открывать и они.

### 3. Мобильное меню
- Та же секция: строка «👤 Имя» + те же пункты списком (без вложенного дропдауна — лучше для touch-навигации), «Выйти» закрывает меню.
- Гость видит «Профиль» / «Войти» — как было.

### 4. UX-детали
- Пока `auth.me` грузится — скелетон вместо кнопки (нет «прыжка» макета при входе).
- Дропдаун закрывается: по клику вне, по `Escape`, при смене роута.
- `aria-haspopup="menu"`, `aria-expanded`, `role="menu"`/`role="menuitem"` — доступность для скринридеров.
- Имя берётся из `firstName`, fallback — префикс email или «Клиент».

## Почему это лучшая практика
- **Постоянный контекст**: клиент не «улетает» в другой раздел после входа, навигация по сайту не прерывается.
- **Discoverability**: имя + иконка в шапке — стандартный паттерн (Nielsen Norman, Material Design), пользователь узнаёт свой аккаунт и видит точку входа в кабинет.
- **Быстрые действия**: «Новая запись» из дропдауна — путь в 2 клика до записи, что напрямую поддерживает конверсию.
- **Никакого дублирования**: Header расширен, логика меню вынесена в один компонент, паттерн дропдауна повторяет уже существующий `DashboardHeader`.

## Безопасность: не менялось
- Аутентификация (httpOnly cookies, JWT refresh-семейства) — не тронута
- CSRF-защита мутаций (включая `auth.logout`) — не тронута
- Middleware / RBAC / ролевые проверки / аудит / rate-limit — не тронуты
- Дропдаун рендерится только на клиенте, данные имени — из защищённой процедуры `auth.me` (`retry: false` — при 401 показывает гостевой блок без лишних запросов)
