# Улучшение навигации и UX авторизованного клиента

## Задача
Сделать единый сайт: одинаковая навигация на всех публичных страницах, `/master` — часть общего сайта, у авторизованного клиента — круглая аватарка с инициалами + имя + меню «Профиль / История записей / Выйти». Без изменения архитектуры, auth flow и безопасности.

## Изменённые файлы

| Файл | Изменение |
|------|-----------|
| `src/app/master/page.tsx` → `src/app/(public)/master/page.tsx` | **Перемещён** в public-группу — наследует общий Header/Footer. URL `/master` сохранён (SEO не тронут), удалён избыточный `MobileBackButton` |
| `src/components/shared/user-menu.tsx` | Круглая аватарка с инициалами + имя (скрывается на мобильных), меню «Профиль / История записей / Выйти», скелетон под мобильный размер |
| `src/components/shared/header.tsx` | Блок пользователя виден на всех экранах (аватар на мобильных рядом с бургером), «Записаться» — desktop + мобильное меню |

Ранее (в рамках этой же задачи): `user-menu.tsx` создан, Header расширен, оба логин-роута возвращают CLIENT на `/`.

## Почему выбран такой подход

### 1. Единый Header/Navbar
- Навигация уже была вынесена в `(public)/layout.tsx` (Header + Footer + отступ под фиксированную шапку) — все публичные страницы (Главная, Услуги, Портфолио, Отзывы, Контакты, инфо-страницы) используют её автоматически.
- **Проблема**: `/master` лежал вне группы `(public)` → рендерился без Header/Footer как «отдельная страница».
- **Решение**: перемещение в `(public)/master` (App Router route group не меняет URL). Вкладка «Мастер» подсвечивается штатно через `pathname === link.href` в `header.tsx`. Никакого отдельного layout — минимальный рефакторинг без дублирования.

### 2. Поведение авторизованного клиента
- Гость: справа «Войти» (+ «Профиль» на md+, «Записаться» на md+ и в бургере).
- Клиент: круглая аватарка с инициалами (`[АМ]`) — паттерн уже использован в `DashboardHeader`; имя рядом скрывается на мобильных (`hidden sm:block`) — не ломает вёрстку.
- Меню: **Профиль** → `/profile`, **История записей** → `/profile` (раздел истории), **Выйти** → `auth.logout` + инвалидация кэша + `/`.
- Для BARBER/ADMIN/SUPER_ADMIN пункты ведут в их кабинеты — публичную шапку могут открывать и они.

### 3. Получение пользователя
- Только `trpc.auth.me` (httpOnly cookies + tRPC ctx) с `retry: false` — при 401 мгновенный переход в гостевой вид без лишних запросов. Никаких localStorage, новых cookies, правок middleware или CSRF.

### 4. Responsive
- Мобильная шапка: аватар (только инициалы) + бургер; вкладки и пункты меню — в бургере списком (без вложенных дропдаунов — удобнее для touch).
- Меню закрывается: клик вне, `Escape`, смена роута. `role="menu"`/`aria-haspopup`/`aria-expanded` для скринридеров.
