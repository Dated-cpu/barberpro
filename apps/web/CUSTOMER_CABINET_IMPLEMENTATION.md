# Клиентский кабинет BarberPro — полноценный продукт

## Задача
Превратить клиентский кабинет из набора блоков в полноценный сервис: внутренняя навигация, обзор, будущие записи, история, настройки. Без изменения auth/security слоя.

## Новые возможности
- **Внутренняя навигация**: вкладки с иконками, активная подсвечена, URL-состояние (`/profile?tab=history`) — ссылки из шапки ведут сразу в нужный раздел, кнопка «Назад» браузера работает.
- **Обзор**: имя, «Клиент с {дата регистрации}», визиты / потрачено / средний чек / последний визит, любимая услуга (со ссылкой «Записаться»), ближайшая запись с отменой, кнопки «Записаться снова» и «Повторить последнюю запись» (префилл услуг в `/booking?services=...` — существующая логика повторной записи).
- **Мои записи**: все будущие записи (PENDING/CONFIRMED), статус-бейджи, время начала/конца, услуги, стоимость; «Отменить» с двушаговым подтверждением через существующий `appointment.cancel` (CSRF-защищён); «Детали» — филиал, барбер, номер записи, статус оплаты, комментарий.
- **История**: переиспользован `AppointmentHistory` (фильтры Месяц/Год, пагинация «Показать ещё», «Повторить запись»).
- **Настройки**: имя/фамилия/email/телефон через `auth.updateProfile`, смена пароля через `auth.changePassword`, «Выйти» / «Выйти из всех устройств» через `auth.logout`/`auth.logoutAll`.
- **Empty states**: «У вас пока нет записей» + «Записаться впервые»; пустые состояния статистики и ближайшей записи уже были — сохранены.
- **Responsive**: табы скроллятся на мобильных (overflow-x-auto), карточки перестраиваются, формы одноколоночные на узких экранах.

## Безопасность: подтверждено, не менялось
- Все новые/существующие процедуры — `protectedProcedure`, `clientId` берётся только из `ctx.user!.id` (JWT из httpOnly cookie). **Передать чужой userId невозможно — ни один метод не принимает его на входе.**
- `appointment.cancel` → сервис вызывает `assertAppointmentAccess(user, clientId, barberId)` — клиент отменяет только свои записи.
- `appointment.getById` → `assertAppointmentAccess` в роутере.
- `auth.updateProfile` / `changePassword` / `logout` / `logoutAll` — существующие процедуры с rate-limit и аудитом, не тронуты.
- CSRF, middleware, RBAC, аудит, rate-limit — не изменены. Новых хранилищ (localStorage/cookies) не добавлено.
